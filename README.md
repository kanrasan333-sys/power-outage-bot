# power-outage-bot

Telegram-бот, который пишет, когда **пропадает и возвращается свет**. Данные берёт
у гибридного инвертора через облако **SmartESS / DESS Monitor** (dessmonitor.com) —
туда их отправляет WiFi-модуль Eybond, который стоит во многих инверторах.

*Telegram alerts for grid power outages and restores, based on hybrid inverter data
from the SmartESS / DESS Monitor (Eybond) cloud.*

```
🔴 Свет пропал (замечено в 18:42)
Дом на аккумуляторе: 51.8 В, нагрузка 640 Вт

🟢 Свет вернулся (замечено в 21:15)
Сеть 226 В · не было 2 ч 33 мин
```

## Зачем

Когда дом питается от аккумулятора, на главном экране SmartESS не видно, есть ли сеть,
и приложение не присылает уведомлений об отключении. В приоритете **SBU** инвертор весь
день работает в режиме «Off-Grid» и при живой сети, поэтому по режиму работы аварию
не отличить от обычного дня.

Бот смотрит не на режим, а на **напряжение сети на входе инвертора**: около 220 В —
свет есть, около 0 В — нет.

## Что умеет

- 🔴 / 🟢 — уведомления о пропаже и возврате света, с длительностью отключения;
- ⚠️ — предупреждение, если данные от инвертора перестали приходить: иначе тишину
  не отличить от «всё хорошо»;
- `/power` — есть ли свет прямо сейчас, напряжение, аккумулятор, нагрузка;
- уведомления, которые не удалось отправить (например, лёг интернет), уходят позже
  с пометкой «с опозданием».

## Что нужно

- Инвертор с WiFi-модулем **Eybond**, который виден в приложении **SmartESS** или
  **DESS Monitor**, и логин от этого приложения.
- Компьютер, Raspberry Pi или сервер с **Python 3.9+**, который работает круглосуточно.
  Если он дома, то он, роутер и интернет должны сами переживать отключение — например,
  быть запитаны от того же инвертора.
- Свой Telegram-бот (создаётся за минуту, см. ниже).

Проверено на Anenji ANJ-6200W-48V-WIFI (платформа Sumry / SMG II). С другими
инверторами за модулем Eybond тоже должно работать: если название параметра у
вашей прошивки другое, его можно указать вручную (см. «Если бот не нашёл напряжение»).

## Установка

```bash
git clone https://github.com/kanrasan333-sys/power-outage-bot.git
cd power-outage-bot
pip install -r requirements.txt
```

**1. Создайте Telegram-бота.** Напишите [@BotFather](https://t.me/BotFather)
команду `/newbot`, придумайте имя. Он пришлёт токен вида `1234567890:AAH...`.

**2. Заполните настройки.** Скопируйте `config.example.json` в `config.json` и впишите:

```json
{
  "telegram_token": "токен от BotFather",
  "telegram_chat_id": 0,
  "dess_user": "логин SmartESS",
  "dess_password": "пароль SmartESS"
}
```

**3. Узнайте chat id.** Запустите `python power_bot.py` и напишите своему боту `/start`.
Пока `telegram_chat_id` равен 0, бот отвечает id этого чата. Впишите его в
`config.json` и перезапустите бота. Можно указать id группы — тогда уведомления
придут туда.

**4. Проверьте.**

```bash
python power_bot.py --check
```

Покажет, принят ли токен Telegram и логин облака, все параметры инвертора и
какое из них бот считает напряжением сети. «Работает» означает «ключ принят» —
и ничего больше.

```bash
python power_bot.py --test
```

Пришлёт тестовое сообщение с текущим состоянием.

**5. Запустите** `python power_bot.py` — и настройте автозапуск.

## Автозапуск

**Windows** — через автозагрузку, без чёрного окна (`pythonw.exe`). Подставьте
свои пути; путь к Python покажет `py -c "import sys; print(sys.executable)"`.

```bat
reg add HKCU\Software\Microsoft\Windows\CurrentVersion\Run /v PowerOutageBot /t REG_SZ /d "\"C:\Python312\pythonw.exe\" \"C:\power-outage-bot\power_bot.py\"" /f
```

Планировщик заданий тоже подойдёт, но у задач по умолчанию стоит «остановить через
3 дня» — эту галочку нужно снять, иначе бот через три дня молча выключится.

**Linux / Raspberry Pi** — `/etc/systemd/system/power-outage-bot.service`:

```ini
[Unit]
Description=power-outage-bot
After=network-online.target
Wants=network-online.target

[Service]
WorkingDirectory=/home/pi/power-outage-bot
ExecStart=/usr/bin/python3 power_bot.py
Restart=always
RestartSec=30
User=pi

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now power-outage-bot
```

## Настройки

| Параметр | По умолчанию | Что это |
|---|---|---|
| `telegram_token` | — | токен бота от @BotFather |
| `telegram_chat_id` | `0` | куда слать уведомления; 0 — бот подскажет id |
| `dess_user`, `dess_password` | — | логин и пароль SmartESS / DESS Monitor |
| `dess_company_key` | ключ веб-клиента dessmonitor.com | менять, только если вход не проходит |
| `device_pn` | первое устройство | PN инвертора, если их в аккаунте несколько |
| `grid_voltage_field` | автоопределение | название параметра с напряжением сети |
| `grid_min_volts` | `50` | ниже этого напряжения считаем, что сети нет |
| `poll_seconds` | `60` | как часто забирать данные из облака |
| `stale_minutes` | `20` | через сколько минут без данных предупредить |
| `listen_commands` | `true` | слушать команды `/power`; `false` — только уведомления |

## Как это работает и ограничения

- WiFi-модуль инвертора сам отправляет данные в облако, обычно **раз в ~5 минут**
  (платная опция Eybond «ускоренный сбор данных» — раз в минуту). Бот забирает
  последнюю точку раз в минуту, поэтому уведомление приходит с задержкой до
  ~6 минут, а **отключение короче 5 минут бот может не заметить**.
- К самому модулю бот не обращается. У модулей Eybond слабый веб-сервер: от частых
  запросов он виснет, и оживает модуль только после того, как его вынуть и вставить обратно.
- Время в сообщениях — время вашего компьютера в момент, когда бот увидел новую
  точку. Часы облака живут в своём часовом поясе, на них бот не опирается.
- Если облако или интернет недоступны дольше `stale_minutes`, бот предупредит, что
  ослеп, а когда данные вернутся — скажет, изменилось ли что-то за это время.
- Если облако отказало во входе (неверный пароль), бот повторяет попытку раз в
  30 минут, чтобы аккаунт не заблокировали за перебор.

## Если бот не нашёл напряжение

Запустите `python power_bot.py --check`. В списке параметров найдите строку с
напряжением сети на входе (у разных прошивок она называется `Grid Voltage`,
`AC Input Voltage`, `Mains Voltage`…) и впишите её название в `config.json`:

```json
"grid_voltage_field": "AC Input Voltage"
```

## Частые вопросы

**`getUpdates: Conflict` в логе.** Этот токен уже слушает другая программа (другой бот).
Telegram разрешает только одного слушателя. Создайте для уведомлений отдельного бота или
поставьте `"listen_commands": false`: уведомления продолжат приходить, не будет только `/power`.

**Где хранится пароль?** Только в `config.json` у вас на компьютере. Файл в
`.gitignore`, в репозиторий не попадёт. Токен и пароль бот вырезает из своего лога.

**Проверить логику без инвертора:** `python -m unittest -v`.

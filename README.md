# power-outage-bot

Telegram-бот, який пише, коли **зникає і повертається світло**. Дані бере
в гібридного інвертора через хмару **SmartESS / DESS Monitor** (dessmonitor.com) —
туди їх надсилає WiFi-модуль Eybond, що стоїть у багатьох інверторах.

*Telegram alerts for grid power outages and restores, based on hybrid inverter data
from the SmartESS / DESS Monitor (Eybond) cloud.*

```
🔴 Світло зникло (помічено о 18:42)
Будинок на акумуляторі: 51.8 В, навантаження 640 Вт

🟢 Світло повернулося (помічено о 21:15)
Мережа 226 В · не було 2 год 33 хв
```

Бот пише українською або англійською — налаштування `language` (`uk` або `en`).
*The bot speaks Ukrainian or English — set `"language": "en"` in config.json.*

## Навіщо

Коли будинок живиться від акумулятора, на головному екрані SmartESS не видно, чи є
мережа, і застосунок не надсилає сповіщень про відключення. У пріоритеті **SBU**
інвертор цілий день працює в режимі «Off-Grid» навіть за наявної мережі, тож
за режимом роботи аварію не відрізнити від звичайного дня.

Бот дивиться не на режим, а на **напругу мережі на вході інвертора**: близько 220 В —
світло є, близько 0 В — немає.

## Що вміє

- 🔴 / 🟢 — сповіщення про зникнення і повернення світла, з тривалістю відключення;
- ⚠️ — попередження, якщо дані від інвертора перестали надходити: інакше тишу
  не відрізнити від «усе добре»;
- `/power` — чи є світло просто зараз, напруга, акумулятор, навантаження;
- сповіщення, які не вдалося надіслати (наприклад, ліг інтернет), надходять пізніше
  з позначкою «із запізненням».

## Що потрібно

- Інвертор з WiFi-модулем **Eybond**, який видно в застосунку **SmartESS** або
  **DESS Monitor**, і логін від цього застосунку.
- Комп’ютер, Raspberry Pi або сервер з **Python 3.9+**, що працює цілодобово.
  Якщо він удома, то він, роутер та інтернет мають самі переживати відключення —
  наприклад, бути заживленими від того ж інвертора.
- Власний Telegram-бот (створюється за хвилину, див. нижче).

Перевірено на Anenji ANJ-6200W-48V-WIFI (платформа Sumry / SMG II). З іншими
інверторами з модулем Eybond теж має працювати: якщо у вашій прошивці параметр
називається інакше, його можна вказати вручну (див. «Якщо бот не знайшов напругу»).

## Встановлення

```bash
git clone https://github.com/kanrasan333-sys/power-outage-bot.git
cd power-outage-bot
pip install -r requirements.txt
```

**1. Створіть Telegram-бота.** Напишіть [@BotFather](https://t.me/BotFather)
команду `/newbot`, придумайте ім’я. Він надішле токен вигляду `1234567890:AAH...`.

**2. Заповніть налаштування.** Скопіюйте `config.example.json` у `config.json` і впишіть:

```json
{
  "language": "uk",
  "telegram_token": "токен від BotFather",
  "telegram_chat_id": 0,
  "dess_user": "логін SmartESS",
  "dess_password": "пароль SmartESS"
}
```

**3. Дізнайтеся chat id.** Запустіть `python power_bot.py` і напишіть своєму боту
`/start`. Поки `telegram_chat_id` дорівнює 0, бот відповідає id цього чату. Впишіть
його в `config.json` і перезапустіть бота. Можна вказати id групи — тоді сповіщення
надходитимуть туди.

**4. Перевірте.**

```bash
python power_bot.py --check
```

Покаже, чи прийнято токен Telegram і логін хмари, усі параметри інвертора і який
із них бот вважає напругою мережі. Статус «працює» означає лише «ключ прийнято».

```bash
python power_bot.py --test
```

Надішле тестове повідомлення з поточним станом.

**5. Запустіть** `python power_bot.py` — і налаштуйте автозапуск.

## Автозапуск

**Windows** — через автозавантаження, без чорного вікна (`pythonw.exe`). Підставте
свої шляхи; шлях до Python покаже `py -c "import sys; print(sys.executable)"`.

```bat
reg add HKCU\Software\Microsoft\Windows\CurrentVersion\Run /v PowerOutageBot /t REG_SZ /d "\"C:\Python312\pythonw.exe\" \"C:\power-outage-bot\power_bot.py\"" /f
```

Планувальник завдань теж підійде, але за замовчуванням він зупиняє завдання після
3 днів роботи — цей прапорець треба зняти, інакше бот через три дні мовчки вимкнеться.

**Linux / Raspberry Pi** — `/etc/systemd/system/power-outage-bot.service`:

```ini
[Unit]
Description=power-outage-bot
After=network-online.target
Wants=network-online.target

[Service]
WorkingDirectory=/home/pi/power-outage-bot
ExecStart=/usr/bin/python3 power_bot.py
Restart=always
RestartSec=30
User=pi

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now power-outage-bot
```

## Налаштування

| Параметр | За замовчуванням | Що це |
|---|---|---|
| `language` | `uk` | мова повідомлень: `uk` — українська, `en` — English |
| `telegram_token` | — | токен бота від @BotFather |
| `telegram_chat_id` | `0` | куди надсилати сповіщення; 0 — бот підкаже id |
| `dess_user`, `dess_password` | — | логін і пароль SmartESS / DESS Monitor |
| `dess_company_key` | ключ вебклієнта dessmonitor.com | змінювати, лише якщо вхід не проходить |
| `device_pn` | перший пристрій | PN інвертора, якщо їх в акаунті кілька |
| `grid_voltage_field` | автовизначення | назва параметра з напругою мережі |
| `grid_min_volts` | `50` | нижче цієї напруги вважаємо, що мережі немає |
| `poll_seconds` | `60` | як часто забирати дані з хмари |
| `stale_minutes` | `20` | через скільки хвилин без даних попередити |
| `listen_commands` | `true` | слухати команду `/power`; `false` — лише сповіщення |

## Як це працює та обмеження

- WiFi-модуль інвертора сам надсилає дані в хмару, зазвичай **раз на ~5 хвилин**
  (платна опція Eybond «прискорений збір даних» — раз на хвилину). Бот забирає
  останню точку раз на хвилину, тому сповіщення надходить із затримкою до ~6 хвилин,
  а **відключення, коротше за 5 хвилин, бот може не помітити**.
- До самого модуля бот не звертається. У модулів Eybond слабкий вебсервер: від частих
  запитів він зависає, і оживає модуль лише після того, як його вийняти й вставити назад.
- Час у повідомленнях — час вашого комп’ютера в момент, коли бот побачив нову точку.
  Годинник хмари живе у своєму часовому поясі, на нього бот не спирається.
- Якщо хмара або інтернет недоступні довше за `stale_minutes`, бот попередить, що
  осліп, а коли дані повернуться — скаже, чи змінилося щось за цей час.
- Якщо хмара відмовила у вході (неправильний пароль), бот повторює спробу раз на
  30 хвилин, щоб акаунт не заблокували за перебір.

## Якщо бот не знайшов напругу

Запустіть `python power_bot.py --check`. У списку параметрів знайдіть рядок із
напругою мережі на вході (у різних прошивках він називається `Grid Voltage`,
`AC Input Voltage`, `Mains Voltage`…) і впишіть його назву в `config.json`:

```json
"grid_voltage_field": "AC Input Voltage"
```

## Часті питання

**`getUpdates: Conflict` у лозі.** Цей токен уже слухає інша програма (інший бот).
Telegram дозволяє лише одного слухача. Створіть для сповіщень окремого бота або
поставте `"listen_commands": false`: сповіщення надходитимуть і далі, не буде лише `/power`.

**Де зберігається пароль?** Лише в `config.json` на вашому комп’ютері. Файл
у `.gitignore`, у репозиторій не потрапить. Токен і пароль бот вирізає зі свого логу.

**Інша мова.** Усі тексти бота — у `texts.py`. Скопіюйте блок `"en"` під новим кодом мови
і перекладіть значення; тести перевірять, що ключі та підстановки збігаються.

**Перевірити логіку без інвертора:** `python -m unittest -v`.
